# 캐릭터 애니메이션

2026-10-16. 홈 카드와 계정 상세에 같은 LVGL 애니메이션을 적용했습니다.

| 표시 상태 | 움직임 |
|---|---|
| 정상 | 천천히 숨쉬기, 짧은 표정 변화·눈깜박임, 가끔 몸 기울이기와 작은 반동 |
| 주의: 잔여 ≤20% | 숨쉬기와 짧게 좌우 살피기 |
| 긴급: 잔여 ≤10% | 간헐적으로 짧은 떨림과 긴급 표정 |
| 소진: 잔여 0% | 지친 자세로 느리게 호흡 |
| 확인 불가 | offline 표정과 느린 호흡 |
| 오래된 정보 | stale 표정과 간헐적인 좌우 움직임 |

Codex·Cursor·Claude·Grok은 기존 [F108pro 저장소](https://github.com/guyster323/F108pro_Usage_monitor)의 검토된 MIT 리비전 `ddab71ab58e353a0b9d1a60274ae9a1a05b0d965`에서 두 번째 표정 24장을 복원했습니다. 원본 PNG를 기존 RGB565+alpha와 동일한 픽셀이 되는 팔레트 형식으로 컴파일합니다. Copilot은 기존 비트맵과 LVGL 눈꺼풀 그리기를 조합해 정상 상태에서 눈을 깜박입니다. 모든 제공자는 상태별 몸동작을 사용합니다.

눈깜박임은 대략 3.7~6.7초마다 짧게, 큰 몸동작은 대략 8.3~12.3초마다 나타납니다. 제공자와 계정 ID로 주기·시점을 달리해 같은 Codex가 여러 개 있어도 각기 다른 위상으로 움직입니다. 스냅샷이 들어와도 전역 LVGL 시계의 동작 위상을 유지합니다. BLE 연결이 끊겨 계정이 삭제되면 기존 화면 정책대로 캐릭터도 사라집니다.

## 자원 사용

- 타이머 하나가 100ms 간격으로 현재 화면의 최대 5개 캐릭터만 살핍니다. 실제 위치·표정·눈꺼풀이 바뀌었을 때만 해당 이미지에 갱신을 요청합니다.
- 설정·계정 선택·페어링 화면과 빈 화면에서는 타이머를 정지합니다. 화면 삭제 전에 이미지 참조를 해제합니다.
- 정수 픽셀 이동만 사용합니다. 상세 화면은 같은 자산을 2배로 표시합니다. 별도 애니메이션 캔버스는 없습니다.
- 원래 정적 30장 855,360바이트에서 애니메이션용 54장 **521,289바이트**로, 자산 저장량을 약 39.1% 줄였습니다. Copilot 비트맵은 중복 저장하지 않습니다.
- 팔레트 디코더는 모든 이미지가 함께 사용하는 고정 28,512바이트 버퍼 하나에 RGB565+alpha를 복원합니다. 프레임별 힙 할당 없이 순차 렌더하며, 캐시가 0이 아닌 설정은 빌드 오류로 차단합니다. RGB565 픽셀과 alpha를 그대로 보존합니다.
- 현재 보드는 코드·rodata를 PSRAM으로 복사합니다. 그래서 플래시 적합성과 별도로 링커의 MMU 페이지 단위 XIP 예약량, LCD 버퍼 2개(1,536,000바이트), 외부 LVGL 스택(16,384바이트)을 합산하고 512KiB 이상의 동적 메모리 여유 추정치를 요구합니다. `python tools/verify_animation_budget.py`로 검사하며, 실제 부팅 후 가용 힙 측정값은 아닙니다.
- 최종 펌웨어 크기·해시는 [빌드 기록](character-animation-build.json)을 참조하세요. 이전 펌웨어의 업로드·실물 검증 기록은 이 변경의 실물 검증을 뜻하지 않습니다.

ESP-IDF 5.5.3의 애니메이션 기본 빌드는 프로그램 6,029,411바이트(72.4%), 정적 RAM 54,032바이트(16.5%)였습니다. 후속 계측 빌드는 프로그램 6,032,263바이트(72.5%), 정적 RAM 55,888바이트(17.1%)입니다. XIP·두 화면 버퍼·LVGL 스택 이후 PSRAM 예산 여유는 872,448바이트(852KiB)로 추정하며, 실제 allocator가 보고한 가용 PSRAM은 912,804바이트(약 891KiB)였습니다. [CPU·FPS·메모리 실측](RUNTIME_METRICS.md)은 예산 추정과 별도로 기록합니다.

주기적인 하단 깨짐·화면 밀림 보고 후 CPU 계측의 전체 태스크·스택 순회를 제거했습니다. 수정 빌드는 프로그램 6,031,679바이트(72.5%), 정적 RAM 54,160바이트(16.5%)이며, 태스크 정보 배열 제거로 정적 RAM을 1,728바이트 줄였습니다. 애니메이션·압축 자산·LCD 타이밍·프레임버퍼 구성은 동일합니다. [지연 원인 분석과 수정 후 검증](RUNTIME_METRICS.md)을 참조하세요.

후속 [다국어·화면 예약](LANGUAGES_AND_SCREEN_SCHEDULE.md) 펌웨어는 추가 글꼴을 포함해 프로그램 74.9%·정적 RAM 16.6%이며, 홈 60.266초 실측 CPU 6.23%·7.48fps·가용 PSRAM 651,272바이트입니다. 화면이 꺼지면 캐릭터 타이머를 정지하고 터치 점등 시 재개합니다.

GIF는 공유 LVGL 코드가 실제 렌더한 800×480 프레임이며 사용량은 예시입니다. 검사에서는 제공자 5종×상태 6종의 움직임·표정, Copilot 눈꺼풀의 실제 픽셀 변화, 캐릭터 영역 밖 숫자·문구·막대의 불변, 상세 화면, 스냅샷 적용, 40회 화면 전환 후 타이머 수·힙 유지, 설정·연결 상실 시 갱신 정지를 확인합니다. 54개 팔레트 자산을 원본 RGB565 변환 결과와 비교하며, 개발 중 비압축 렌더 380프레임과 팔레트 렌더의 SHA-256도 모두 일치했습니다. 네이티브 힙 검사는 ESP32의 동적 메모리 측정과는 다릅니다.

2026-10-16 실물 적용을 완료했습니다. COM5의 ESP32-S3 / 16MB flash / 8MB PSRAM을 확인하고, 기존 앱을 백업해 이전 펌웨어 해시와 일치함을 검사했습니다. `0x10000` 앱 영역만 교체한 뒤 새 이미지의 플래시 검증과 `0x0..0xffff` 부트로더·파티션·NVS 영역의 업로드 전후 바이트 일치를 확인했습니다. 기존 앱 백업은 비공개 `.local/board-character-animation-20261016/`에 보관합니다.

사용자는 화면 기동 후 연결이 되지 않는다고 알렸고, PC BLE 도우미 재시작 후 BLE 연결·정상 동작을 확인했습니다. 후속 계측 펌웨어에서는 기존 BLE 알림으로 실제 CPU·LVGL 갱신 FPS·PSRAM을 수집했고, 사용자가 연 상세 화면도 비교했습니다. 개별 모션의 시각적 직접 관측·별도 snapshot ACK 수집·터치 스트레스 검사는 수행하지 않았습니다. USB 콘솔 수집은 0바이트였으며 후속 기동은 인증된 실물 BLE 통계로도 검증했습니다.

자산만 다시 컴파일할 때는 `python tools/generate_native_assets.py --sprites-only`를 사용합니다. 기존 폰트와 LVGL 설정은 유지하며, 기존 생성기와 같이 고정 리비전의 `references/f108pro` 체크아웃이 필요합니다. 일반 펌웨어·네이티브 빌드는 커밋된 생성 자산을 사용하므로 참조 저장소나 이미지 생성 서비스가 필요하지 않습니다.
